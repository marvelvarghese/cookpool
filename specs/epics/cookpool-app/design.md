# cookpool-app — design

## 1. What is there today

CP-23 made Cookpool installable:
- `/manifest.webmanifest` (a route, built per deploy): `display: standalone`, `start_url` and `id` `/home`, portrait, theme `#1F7A4D`.
- Icons: 192, 512, a maskable 512, an SVG and the Apple touch icon.
- The root layout: `viewport-fit=cover`, `appleWebApp` capable with a black-translucent status bar, and safe-area helpers in `globals.css`.

There is no service worker, no install invitation and no gesture. SM-2 made every Cookpool page a static file with a static client-navigation payload, which suits a service worker: the app's whole shell is a known list of files per build.

## 2. An app on your home screen (PW1)

- **The invitation, once, as the phone allows.**
  - **Android and desktop Chrome** fire `beforeinstallprompt`. Home shows one card, "Install Cookpool · Open it like an app", with Install (the browser's own prompt) and ✕.
  - **iPhone Safari** has no prompt. The same card opens a sheet with the two steps drawn ("Share", then "Add to Home Screen").
  - **When:** from the second day someone uses Cookpool, never in the installed app. ✕ hides it for 30 days. "Install the app" stays in You.
- **The manifest grows:**
  - `shortcuts` (long-press the icon): Log a use, Bought food, Cook.
  - `screenshots`, so Android shows a richer install sheet.
  - The `id` stays `/home`, so existing installs keep working.
- **iPhone polish:** splash images (`apple-touch-startup-image`) for the common sizes, generated at build from the icon and background colour.
- **Without browser chrome:**
  - Every screen that is not a tab has a back control in its header.
  - A screen opened directly (a link, a shortcut) goes back to its parent, not off the app.
  - The body doesn't rubber-band (`overscroll-behavior: none` on the app root, with scrolling inside).
  - No double-tap zoom on controls (`touch-action: manipulation`), no text selection on buttons, `100dvh`.
  - The focused field scrolls above the keyboard.
- **Standalone, not fullscreen:** the status bar keeps the time and battery, and iPhones treat "fullscreen" as standalone anyway.

## 3. No signal, clean updates (PW2)

- **A service worker of our own** (no Workbox), generated by the build next to `pages-as-files`.
  - It precaches the current build's static pages, their `/_rsc/*.rsc` payloads, `/_next/static/*` and the icons.
  - Pages and payloads are network-first with a 3 s cutoff, then the cache. Hashed static files are cache-first.
  - The SM-2 RSC shim and SM-4's `/api` keep working through it.
- **The last-seen data, per account.** `/api` GETs that read a person's own screens (Home, pantries, items, dishes, groups, people) go into a cache named for the signed-in account. Each request goes to the network first, with the last answer kept for when there's no signal.
  - Sign-out deletes that account's cache.
  - Nothing that authenticates (tokens, codes) is ever cached.
- **Offline.**
  - A thin banner reads "Offline · showing what you saw last".
  - Every write button stays visible but held back: tapping it shows "You're offline".
  - Nothing is queued. When the signal returns, the banner goes and the screen refreshes.
- **Updates.**
  - A new build installs in the background, and a toast offers "New version · Reload".
  - The toast never appears while a write is in flight (SM-5's `afterWrites`).
  - An app left open for a day reloads itself on its next launch.

## 4. Notifications and the badge (PW3)

- **What it is:** Web Push from notifications-worker, sent with a VAPID key (a secret, brokered like the others).
  - Subscriptions are stored per device: a `notification_subscriptions` table and a route to add or remove one.
  - Three kinds, each on or off in You: "Anu said you had 1 portion of Egg fried rice", "Egg fried rice is ready to claim", "Dev paid you ₹400".
  - The icon badge shows Home's to-do count (the Badging API).
- **On iPhone it works only for the installed app (iOS 16.4+).** In the browser, the setting explains that.
- **Email stays as it is.** Push is in addition to email, not instead of it.
- **The ask comes after a choice, never on launch.** You → Notifications lists the three kinds, all off. Turning one on is what asks the phone for permission. On an iPhone in the browser, the switches are replaced by one line: "Add Cookpool to your Home Screen to get notifications."
- **Who sends what.** kitchen-worker already emails "Anu said you had 1 portion…" (SM-6) and the dish and payment events go through notifications-worker. Push is a second channel on the same events, with the same once-per-dish-and-person keys.

## 5. Gestures (PW4)

Each one is a small pointer-events hook with CSS transforms, with no animation library. Each respects `prefers-reduced-motion`, and each has a visible twin:

| Gesture | Where | What it does | Its twin |
|---|---|---|---|
| Pull down at the top | Home, Pantry, Groups, a group, People, a person, a dish | Refreshes, with a spinner in the pull | Data refreshes on focus as today |
| Swipe from the left edge | Any non-tab screen, **installed on iPhone only** (Android has its own back; Safari in the browser has its own) | Back, with the page sliding | The header's back control |
| Drag a sheet down | + Add, pickers, the measure question, every bottom sheet | Closes it | ✕ / tapping outside |
| Swipe a pantry row left | Pantry, the use-soon strip | "Use my usual", with the Undo toast | The row's Use button |
| Swipe your own log left | Activity, an item's uses | Undo, with the toast | The row's ⋮ → Undo |
| Long-press an item | Pantry rows, Home's use-soon | Use · Cook with it · Wasted · Open | Opening the item |
| Hold − or + | Every stepper | Repeats, faster after 1 s | Tapping |

**Not gestures:**
- **Paid, Finalize, Leave, delete and money amounts.** These are buttons only, because a mis-swipe must never move money.
- **Swiping between tabs.** It would fight the row swipes, the edge swipe and the carousels.
- **Pinch.**
- **Haptics.** Android may get a short vibrate on a completed swipe, as a bonus; nothing depends on it.

## 6. Out of scope

Native apps; store apps (a Capacitor or TWA wrapper of this same code stays a later option, if people ask); offline writes, background sync, sharing into Cookpool (a share target), camera or receipt scanning, desktop-specific install work beyond what Chrome gives for free.
